丢一个 seed 进去，吐出一张能走的地牢图：有起点、有 Boss、有支线，偶尔还有门和钥匙。同一个 seed 再生成一次，结果不变。

![seed 12345 的可玩视图](/blog/dungeon-gen/play-seed-12345.png)

实现在 [nangongbee/dungeon-gen](https://github.com/nangongbee/dungeon-gen)。这篇文章讲的是它在解决什么问题，以及主线 / 支线 / 钥匙门这三段是怎么卡住的。

## 我要的地牢长什么样

程序化生成一上手很容易变成“随机铺房间”。我真正想要的是一套**关卡节奏**，不是一张随便逛的迷宫。约束大致是这些：

1. **要有推进感。** 从起点走到 Boss 应该像一条主线，而不是整张图上每条路都等价。
2. **要有支线。** 纯直线太无聊；支线接回主线时，又不能把「起点到 Boss」抄得太近。
3. **门要有意义。** 没钥匙不该碰巧绕过去；钥匙必须放在「不经过这扇门也能走到」的地方。找不到合法位置，就宁可拆掉这扇门，也不要出死图。
4. **同 seed 可复现。** 调试和测试都依赖这件事；“看起来随机”不够，还得能重放。

基本单位不是墙和地板格子，而是**房间节点**：每个房间有坐标和邻居，生成结果是一张图。内容（门、钥匙、怪、箱子）挂在节点上。

## 流水线概览

整次生成可以看成三步：

1. 用选择栈铺出主线房间。
2. 沿主线分段往外挂支线；接回主线时检查短路比。
3. 放门、钥匙和其他内容；钥匙不合法就撤门。

默认参数在 `config/default.json`。下面按这三步说。

## 主线：选择栈，而不是一次走死

主线不是“随机朝某个方向一直走”。每一步会看当前格子四周还能去哪，还前瞻一格：新位置至少还要留得出路，不然主线很容易把自己堵死。候选多于一个时就打乱顺序，压进选择栈；当前步没路了就弹栈、撤掉最后一个主线房间、换下一个候选。

顺带卡一下外接矩形的长宽比，避免整条主线拉成一根细长蛇。主线房数来自配置里的区间，例如默认 `mainRooms: [10, 12]`。

这一步失败会返回 `MainPathStuck`，外层用略微偏移的 seed 重试。注意：对同一个原始 seed，生成是确定的，所以重试必须改 attempt seed，否则会在同一条死路上打转。

## 支线：分段挂，接回去时不许抄近路

支线不会挂在起点或 Boss 上。主线去掉两端后切成若干段，支线尽量均匀地挂上去。每条支线先保底一段长度，剩下的房间数再随机撒；某条中途挂失败，没长够的配额会补给还没生成的支线。

真正麻烦的是**接回主线**。如果支线随便连回前面的主线房，玩家可能三两步就抄到 Boss 附近。所以连边前会算「若加上这条边，起点到 Boss 的最短路会不会短于阈值」：

\[
\text{hops} + 1 \ge \lceil \textit{shortcutRatio} \times \textit{mainRooms} \rceil
\]

默认 `shortcutRatio` 是 `0.6`。不满足就换下一个候选点，而不是硬连。

## 门和钥匙：先锁，再找放钥匙的地方

门不是装饰。流程是先放门，再为每扇门找钥匙：钥匙必须落在「不经过这扇门也能到达」的区域。否则玩家可能永远摸不到钥匙，或钥匙掉在门后——两种都算坏关卡。

找不到合法位置，就把这扇门拿掉。听起来像偷懒，实际是明确的产品选择：**总比出死图好**。箱子、精英、普通怪在门钥匙之后再填，规则相对宽松。

## 可以拧的旋钮

| 参数 | 大致影响 |
| --- | --- |
| `mainRooms` | 主线长度，也就是「到 Boss 要走多远」的骨架 |
| `totalRooms` | 主线 + 支线总房数 |
| `subPaths` | 支线条数；太多时空间不够，失败配额会往后扔 |
| `shortcutRatio` | 支线回连时允许的最短路下限，越大越不容易抄近路 |
| `sizeRatioLimit` | 外框长宽比上限，抑制细长图 |
| `doors` / 各类箱子 | 内容密度；门还会受主线长度等内部阈值约束 |

同一套代码，拧这些旋钮就能换手感，而不用重写生成器。旋钮作用在房间图和钥匙门上，改的是关卡节奏，不是迷宫填充密度。

## 怎么知道它没坏

生成器写起来爽，回归才烦人。仓库里用一组不变量兜住常见翻车：

- 同一 seed 两次生成，JSON 字节级一致；换 seed 结果不同
- 图连通；从起点能解到 Boss（含钥匙门逻辑）
- 起点到 Boss 的跳数满足短路比
- 门和钥匙数量一一对应；边是四邻接、无重复邻居
- Session 起步在房间 1；没钥匙时走进锁门会失败

这些在 `tests/test_invariants.cpp` 里跑，CI 会编核心库并执行 `ctest`。可玩窗口是可选的：没有 SDL 也能编过 CLI 和测试。

## 还不满意的地方

诚实说几点。

- **支线有时仍然偏绕。** 短路约束管的是「到 Boss 的最短路」，不管走廊观感；看起来迂的图仍然合法。
- **这是房间图，不是 tile 迷宫。** 没有宽走廊和复杂房间轮廓；战斗空间、掩体之类要另做表现层。
- **过程可视化还弱。** 现在能看最终图和 ASCII；主线弹栈、短路拒边、拆门这些中间态，更适合以后做成逐步回放。那会是下一篇或网页 demo 的事，不是这篇的前置条件。
- **配置 JSON 是手写解析。** 字段固定、依赖少；换通用库能省事，但不是当前瓶颈。

## 自己跑一下

```bash
git clone https://github.com/nangongbee/dungeon-gen.git
cd dungeon-gen
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DDUNGEON_BUILD_PLAY=OFF
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/dungeon_cli --seed 12345
```

有 `libsdl2-dev` 时去掉 `-DDUNGEON_BUILD_PLAY=OFF`，可以编 `dungeon_play` 在窗口里改参数、走路、捡钥匙。

仓库：[github.com/nangongbee/dungeon-gen](https://github.com/nangongbee/dungeon-gen)。若之后补上生成过程的网页回放，我会再写一篇专门讲可视化和事件流。
